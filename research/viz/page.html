    The address space over a compile

    Each strip is one data structure of the self-hosted compiler (each Goose table lives on a data stack of its own), drawn as the bytes it actually used, stacked top to bottom; time runs left to right. Every pixel is a group of memory accesses, colored by the cache level that served them in the simulation, and brighter where there are more of them.

    Bytes moved per stage

    Bytes brought into L1 from each level (64 bytes per line filled), per stage, for both front ends on the same input. The bars share one scale. Bold numbers on the left are L1 hits, which move nothing.

    Where the self-hosted compiler's bytes go

    Every access of the whole compile, by data structure (exact counts, not sampled).

    How this was measured

    Hardware counters (perf, AMD Zen 4 ls_dmnd_fills_from_sys.*, 5 runs) give real totals; a Valgrind tool, research/viz/trace/bytemove.c, replays every load and store through a model of this CPU's caches (L1 32 KB 8-way, L2 1 MB 8-way, L3 32 MB 16-way victim cache, 64-byte lines, LRU, no prefetcher) and records which level served it. The simulation agrees with cachegrind on L1 misses to within 0.1% and with the counters to within the prefetchers' share. Details and evidence: research/viz/METHOD.md.
